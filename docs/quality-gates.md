# Quality gates for pages and features

Use this definition of done for each delivered page or feature. Apply account, booking, and clinical checks when those areas are in scope. Record evidence and unresolved gaps in the delivery notes or pull request.

- **Complete behavior:** Every visible link, button, form, and navigation path reaches the intended result. Forms validate input and show useful success and error messages. Check loading, empty, invalid, unavailable, and failure states, plus cancellation or retry where relevant. Use confirmed clinic content, contact details, and emergency guidance rather than placeholder claims.
- **Layout and accessibility:** Review small and large screens, including long text and the confirmed languages and text directions. Check for clipping, overlap, horizontal scrolling, and controls hidden by headers or dialogs. All actions work by keyboard; focus is visible and moves sensibly; controls have clear labels, errors are announced, and contrast and semantic structure support assistive technology.
- **Accounts and private data:** For any account or clinical feature, verify sign-in and recovery flows, server-side validation and per-record authorization for each relevant role. Deny unauthorized access to pages, actions, files, and direct URLs; audit sensitive record access and clinical changes. Confirm approved consent, privacy, retention, and data-sharing rules before collecting personal or clinical data. Keep secrets and real patient data out of the repository and test fixtures.
- **Verification:** When an application stack exists, run its build, type check, and lint checks. Add and run meaningful unit tests for rules and edge cases, integration tests for data and permission boundaries, and browser flows for the main user journey and key failure paths. For booking, cover conflicts and timezones. Fix failures or document a specific release decision; a passing build alone does not establish that a feature works.
- **Review evidence:** State what was checked, where and how it was checked, and the result. Include relevant screen sizes, roles, test commands, and browser flows. List known gaps, their impact, and the owner or next action. Do not mark a page or feature done while a critical interaction, access control, or privacy requirement remains unverified.

This repository currently contains plans only; these gates do not imply that application code, tests, or CI already exist.
